# SHRS SEO & Growth Operations Manual

The complete operating guide for the school's search and analytics
infrastructure: every account, who owns it, how it is verified, what is
watched and when, and what to do when something breaks. Written so the
Registrar's office can run it without a consultant.

**Status legend** — ✅ built in this repository · 🔑 requires an account only
the school can create · ⏳ becomes relevant later.

---

## 1. Accounts (Tier 1)

### 1.1 Ownership and credentials policy — read this first

- Every account below is created with **one school-owned email**:
  `info@shroyalschools.com` (never a staff member's personal Gmail — staff
  leave; the school's Search Console must not leave with them).
- Two named humans hold access at all times: the **Head of Schools** and one
  deputised officer. Access is reviewed each term.
- Credentials live in a password manager the school controls. Never in a
  spreadsheet, never in WhatsApp, never in this repository.
- Every account gets 2-factor authentication on day one, with recovery codes
  printed and kept with the school's other permanent documents.

### 1.2 Google Search Console 🔑

1. `search.google.com/search-console` → Add property → **Domain** property
   `shroyalschools.com` (covers www/non-www, http/https at once). Verify by
   DNS TXT record at the registrar.
2. Add a second domain property for `shroyalschools.ng` — needed for the
   Change of Address step in the migration.
3. Submit `https://shroyalschools.com/sitemap.xml` (✅ already built: 43 URLs,
   105 hreflang alternates, 43 image entries, regenerated by
   `node scripts/seo-build.mjs`).
4. After the `.ng` redirects deploy: Settings → Change of Address on the
   `.ng` property → point to `.com`.
5. Watch weekly (§6): Indexing → Pages; Performance → queries; Core Web
   Vitals; Security & Manual Actions (should always be empty — if not, it is
   the day's only priority).

### 1.3 Google Business Profile 🔑 — the highest-value account of all

1. `business.google.com` → create/claim **Sultan Hanafi Royal Schools** at
   *15 Imowonla Road, AP Bus Stop, Off Gberigbe–Agura Road, Ikorodu, Lagos
   State* — byte-identical to the site and the entity markup (✅).
2. Primary category **Islamic school**; secondary *Private educational
   institution*, *Boarding school*.
3. Hours exactly as `/contact/` publishes (✅ same hours are in the entity):
   Mon–Wed 07:30–18:00 · Thu–Fri 07:30–16:00 · Sat–Sun 09:00–15:00.
4. Photos: the campus frontage, gate, laboratories, graduation — from the
   gallery, best-resolution versions.
5. Weekly: one Update post (an event, a notice, a photograph). Monthly: seed
   two genuine Q&As from what parents actually ask the office.
6. Reviews: ask in person at parents' evenings and after graduation — a
   printed card with the short review link works. Respond to every review,
   good and bad, within a week. Never buy or fake one: a single exposed fake
   outweighs fifty real ones.
7. Links in the profile carry UTM tags so GA4 can attribute:
   `https://shroyalschools.com/?utm_source=google&utm_medium=organic&utm_campaign=gbp`

### 1.4 Google Analytics 4 🔑 → ✅ instrumentation ready

1. `analytics.google.com` → create property → web stream for
   `shroyalschools.com` → copy the `G-XXXXXXXXXX` measurement ID.
2. Paste it into `CONFIG.ga4` in `js/measure.js`, bump `?v=` in the script
   tag (`scripts/measure-wire.mjs` wired 148 public pages ✅), deploy.
3. The five conversions are already instrumented sitewide by delegation —
   no tags on individual pages, ever:
   `whatsapp_click` · `phone_click` · `email_click` · `file_download` ·
   `form_submit` (plus `outbound_click`, `page_bottom`).
4. In GA4: Admin → Events → mark `whatsapp_click`, `phone_click` and
   `form_submit` as **key events**. These three ARE the admissions funnel.
5. Until an ID is pasted, `measure.js` makes zero requests and sets zero
   cookies — the site ships instrumented but silent.

### 1.5 Bing Webmaster Tools 🔑

`bing.com/webmasters` → **Import from Search Console** (one click, after
1.2) → confirm the sitemap imported. Check monthly. Bing also feeds
ChatGPT's browsing — this is an AI-visibility account, not a vanity one.

### 1.6 Microsoft Clarity 🔑 → ✅ instrumentation ready

`clarity.microsoft.com` → new project → copy the project ID into
`CONFIG.clarity` in `js/measure.js`. Free, no traffic limits. Watch the
admission-form recordings monthly: where parents abandon the ten-step form
is the highest-value UX finding the school can get.

### 1.7 Google Tag Manager ⏳ — deliberately not yet

GTM earns its complexity when non-developers need to add tags. Today every
tag flows through one file (`js/measure.js`) under version control — which
is *stronger* governance than GTM. Revisit when a marketing hire needs
self-service.

## 5. Performance (Tier 5)

- Budgets, enforced by measurement not hope: page HTML ≤ 250 KB; images per
  §`scripts/images-build.py` caps; zero render-blocking third parties (✅ —
  keep it true; any new `<script src>` to a third party needs a reason in
  writing).
- Core Web Vitals: lab-checked in this repo (Playwright harness), field data
  from Search Console once connected. Field beats lab; trust CrUX over local
  numbers.
- Uptime: `uptimerobot.com` free tier on `/` and `/admission/apply/`,
  alerting to the school email. 🔑
- CDN/caching: already on Cloudflare Pages with immutable asset caching ✅.

Monthly one-pager for leadership, from GSC + GA4 exports (Looker Studio 🔑

dashboard):

1. Enquiries: WhatsApp clicks, calls, form submissions (GA4 key events)
2. Organic clicks and impressions, month vs month (GSC)
3. Top 10 queries and top 10 pages
4. Local: GBP calls, direction requests, profile views
5. Technical health: audit output (must read 0 defects), CWV status
6. One decision requested of leadership (never a report without one)

## 8. Disaster recovery

| Failure | Response |
|---|---|
| Site down | Cloudflare Pages status + last deploy; roll back to previous deployment in the Pages dashboard |
| Manual action in GSC | Read the exact violation; fix; file reconsideration with dates and evidence. Never wait it out |
| Account lockout | Recovery codes (§1.1); second owner signs in and re-adds |
| Domain expiry | Registrar auto-renew ON for `.com`, `.ng`, `shrschools.ng`; calendar reminder 60 days out regardless |
| Ranking drop | Check GSC coverage first (deindexing ≠ demotion), then CWV, then recent deploys — in that order, before any panic edits |
| Defacement/hack | Pages rollback; rotate credentials; `security.google.com` review; the archive's hashes (`archive/register.json`) verify what is authentic |
