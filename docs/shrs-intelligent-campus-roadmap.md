# SHRS Intelligent Campus Roadmap

**In response to:** the "SHRS World-Class Digital Campus Directive" and companion "Qur'an Experience Directive" (July 2026).

## Why this document exists

The directive asks for roughly six separate, substantial systems: a genuinely functional AI assistant, an enterprise-grade search engine, a full e-commerce marketplace, a premium event/announcement system, a flagship Qur'an platform (Madinah Mushaf, multi-reciter audio, Hifz mode, tracking), and a long list of "world-class features" (achievement walls, alumni section, media centre, mobile app, and more). Each of those is realistically a multi-week project on its own. This document is the honest map: what shipped in this pass, what was deliberately descoped and why, and what a real next phase looks like — the same "phased, honest roadmap" pattern used throughout this site's build (see `shrs-website-excellence-roadmap.md`, `identity-authentication-roadmap.md`).

## Legal research completed this pass

Two directives explicitly asked for licensing research before implementation. Findings:

| Asset | Licence found | Verdict |
|---|---|---|
| Tanzil Project Qur'an text (Uthmani script) | Creative Commons Attribution 3.0 — verbatim copying/redistribution permitted with attribution + link to tanzil.net | **Safe to use**, once fetched programmatically from a real source |
| KFGQPC Uthmanic Script font (King Fahd Complex) | Free for non-commercial use; cannot be sold, modified, or reverse-engineered | **Safe to use** for Madinah-style typesetting — this is the standard approach other Qur'an apps use instead of the item below |
| Scanned Madinah Mushaf page images (the actual photographic pages) | No comparably clear open licence found; the Complex's own digital-publishing platform requires direct engagement | **Do not use without written permission.** This is the one component of the directive that carries real copyright risk if done carelessly |
| EveryAyah.com reciter audio (Alafasy, Husary, Minshawy, Sudais, Shuraim, Abdul Basit, etc.) | Generally Creative Commons Attribution-NonCommercial; per-file/per-reciter terms vary | **Usable for this non-commercial school site with attribution**, but verify the specific reciter's terms before enabling their voice |
| Cloudflare Workers AI | 10,000 free "Neurons"/day, no card required, then $0.00007–0.00015/1K tokens | A genuine "not-a-separately-paid-API" option for future assistant work, and it's on the same platform (Cloudflare Pages) this site already runs on |

**A hard constraint discovered during this pass, not before:** this working session has no outbound network access to external Qur'an text/audio APIs (confirmed by testing `curl`/`WebFetch` against `api.alquran.cloud` — both blocked, HTTP 403). That means the actual verse text for a real reader could not be fetched and verified here. Consistent with this codebase's existing, deliberate rule (see the Verse-of-the-Day feature in the Personalisation Centre), **no Qur'anic Arabic text was typed from memory into any file this pass** — the risk of a transcription error in sacred text is never worth it, no matter how well-known the verse. This is why the Qur'an Centre shipped as an honest architecture-and-navigation shell rather than a working reader; finishing it needs a session (or the school's own developer) with real API access to Tanzil-sourced data.

## What shipped this pass

1. **Navigation** — Marketplace, Gallery, Press & News Room, and Online Learning Courses added to the header mega-menu (Discover SHRS / Digital Campus panels), footer quick-links grid, and site manifest, EN + AR.
2. **The Marketplace** (`/marketplace/`) — full catalog architecture: a `marketplace_products` table (12 real categories from the directive: textbooks, exercise books, uniforms, bags, stationery, Qur'an materials, Arabic materials, Islamic studies materials, digital products, SHRS publications, grammar books, curriculum materials), a public read API, a token-gated staff admin API (create/update/publish/archive/availability), and a storefront page rendering real product cards once staff publish them. **No live checkout** — every "Enquire to Order" button opens a pre-filled WhatsApp message to the Bursary/Bookshop instead. This is a deliberate, flagged decision: real online payment needs a chosen payment processor (Paystack/Flutterwave are the standard Nigerian options), PCI-relevant compliance, and business/legal setup the school hasn't made yet. Building a fake "Buy Now" button that doesn't actually charge anyone would be worse than being upfront that checkout is coming later.
3. **Press & News Room** (`/press/`) — reuses the real announcements feed (no fabricated press releases) plus a genuinely new Media Kit section: an official boilerplate paragraph, crest/seal downloads, and media-enquiry contact details.
4. **The Campus Gallery** (`/gallery/`) — every real campus photo already in the codebase, organised into four categories (Campus & Facilities, Islamic Life, Academics & Achievement, Boarding & Milestones), EN + AR.
5. **Online Learning Courses** (`/online-courses/`) — an honest shell in the same style as the existing Strategic Plan page: what digital learning already exists (Adhkār Centre, Digital Campus, curriculum pages) versus what's a genuine idea under consideration, not yet funded or scheduled.
6. **Premium event system** — the announcements schema gained `rsvp_count` (a public, unauthenticated, honest tap-counter — no guest list, no name collection) and `gallery_images` (a post-event photo array staff attach once real photos exist). The homepage hero now shows an RSVP button, a Share button (native share sheet or clipboard fallback), and — once an event is archived — its real photo gallery. `docs/announcements-system.md` has the exact curl sequence to publish the 8 August 2026 Academic Graduation Ceremony with all of this; it hasn't been run against production because this workspace has no `PORTAL_ADMIN_TOKEN`.
7. **Enterprise-grade local search** — the search index (`search-index.{lang}.json`) now carries each page's actual body text (stripped of markup), not just its title/description. A search for "Qur'an" now surfaces Qur'an College, Hifz/Ijazah mentions, and Adhkār content wherever those words actually appear on a page, with a highlighted snippet showing why it matched — genuinely searching the site's content, not just its menu.
8. **AI assistant — retrieval grounding (Phase 1)** — `functions/api/chat.js` now scores the same search index against the visitor's message and injects the top 2–3 matching pages' real excerpts into the system prompt before calling the model, so answers about specific curriculum/policy detail are grounded in actual published content rather than general knowledge alone. This is a genuine RAG-lite layer built from infrastructure already in place, not a rewrite of the existing (already-shipped, already-working) Claude-based assistant.
9. **Qur'an Centre** (`/quran-centre/`) — an honest architecture page: what's genuinely live today (Adhkār Centre, Qur'an College's real per-student Hifz/Ijazah tracker, the new homepage "Today's Wird" widget), the research above on what a real reader needs, and a plain explanation of why the reader itself isn't built yet.
10. **"Today's Wird" homepage widget** — the existing "Today's Reflection" Adhkār teaser became a three-part "Today's Wird" band: Today's Adhkār (unchanged, already real), Today's Islamic Reminder (a well-established verse or hadith, English translation + citation, alternating daily — extracted into a shared `js/reflections-data.js` so the homepage and the Personalisation Centre panel draw from one source instead of two drifting copies), and a Qur'an Centre link. No fabricated "today's Qur'an reading" statistic, since there's no real per-visitor reading plan yet.

## What was deliberately NOT built this pass, and why

- **Live Marketplace checkout.** Needs a payment-processor decision and business/legal setup outside a code change — see above.
- **The full Madinah-style Qur'an reader, audio, and Hifz repeat-loop tools.** Needs real, fetched Tanzil/EveryAyah data — see the network-access finding above. The navigation architecture (page/juz'/hizb/surah, manual/auto-scroll, repeat-loop controls) is designed and ready to receive it.
- **Cloudflare Workers AI migration for the assistant.** The existing Claude-based assistant already works and was rebuilt with a warmer, more human tone in the previous pass — ripping it out for an unproven free-tier alternative mid-session would be a regression risk for no immediate gain. Recorded here as the recommended path *if and when* the school wants to reduce or eliminate the assistant's per-message cost: Workers AI runs on the same Cloudflare account already hosting this site, with a genuine free daily allowance.
- **Haystack integration for the Marketplace.** Researched: the cleanest approach is to keep the Marketplace's public read API (`/api/portal/marketplace/list`) as a stable, versioned JSON contract — Haystack (or any other search/RAG framework) can index that feed as an external document store without this codebase needing to embed Haystack itself. No code changes needed today; this is a note for whoever wires it up later.
- **The long "world-class features" list** (Parent/Student/Faculty Resource Centres, Academic/Examination Calendars, Live Result Access, Student Achievement Wall, Alumni Section, Success Stories, University Placement, Hifz/Ijazah Achievement Walls, Research & Publications, Download Centre, Digital Library, Mobile App, Accessibility/SEO/Structured-Data audit, Teacher Development Centre, Media Centre expansion, Virtual Campus Tour). Several of these already exist in some real form (Faculty Directory, the Registrar's Office, the Hifz/Ijazah tracker, the announcements/press system, the campus gallery) and are cross-linked from the new pages above; the rest are genuinely new builds each deserving their own scoped pass rather than a rushed, thin version of all twelve at once. Recommended priority order for a future phase, based on what's closest to already-real: (1) Student/Parent Resource Centre — mostly a matter of linking existing portal features under one banner; (2) Academic/Examination Calendar — real dates exist in `academic_terms`, needs a calendar UI; (3) Alumni/Success Stories — needs real content from the school (photos, names, consent) before anything can be published, same rule as every other image on this site; (4) Accessibility/SEO/structured-data audit — a real, scoped technical pass, not content-dependent, good next-phase candidate; (5) Mobile app — a genuinely large, separate engineering track.

## Recommended next phases (in priority order)

1. **Qur'an Centre Phase 2** — with real network access to Tanzil's API (or the school's own developer running the fetch), wire the actual verse text and Uthmanic-font rendering into the navigation shell already built.
2. **Marketplace Phase 2** — once the school has chosen a payment processor, wire real checkout behind the existing product catalog (no schema changes needed — `marketplace_products` already has everything except a payment reference).
3. **Accessibility/SEO/structured-data audit** — content-independent, high value, good candidate for the next available session.
4. **Academic/Examination Calendar UI** — surfaces data that already exists in `academic_terms`.
5. Everything else in the "world-class features" list, gated on real content (photos, names, consent, achievements) existing first — this site's standing rule throughout its build has been: no fabricated content, ever, even to fill out a feature list.
